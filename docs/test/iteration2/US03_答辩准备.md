# US03 答辩准备文档

日期：2026-04-12

## 1. 我负责的功能

我负责的是 **US03：从简历自动填充个人资料**。

该功能的目标是：

1. TA 上传简历后，系统自动提取教育背景、技能和经历。
2. 提取结果自动预填到 Profile 表单中。
3. 用户可以在保存前手动修改，再保存到个人档案。

一句话概括：

> 我把已有的简历上传功能扩展成了一个完整闭环：上传 CV -> 解析内容 -> 预填表单 -> 用户修改 -> 保存档案。

## 2. 现场演示时怎么讲

建议按下面顺序讲解：

1. 先说明业务问题  
   TA 在填写个人档案时，经常需要把简历里的内容重复输入，所以 US03 的目标是减少重复劳动。

2. 说明功能流程  
   流程是：上传 CV -> 后端解析文本 -> 回填到表单 -> 用户可编辑 -> 保存到档案。

3. 说明自己的实现内容  
   我主要改了五部分：
   - 上传 Servlet
   - CV 业务 Service
   - CV 解析工具类
   - Profile 保存逻辑
   - Profile 页面展示

## 3. 现场演示步骤

1. 使用 TA 账号登录系统。
2. 打开 `profile` 页面。
3. 先展示当前 Profile 表单。
4. 在 `Upload CV` 区域上传一个 `docx` 简历。
5. 展示上传成功提示。
6. 展示 `Programme`、`Skills`、`Experience` 三个字段已被自动填充。
7. 手动修改 `Experience` 或 `Skills` 中的一小段内容。
8. 点击 `Save Profile`。
9. 重新打开页面，证明修改后的内容已经保存。

## 4. 关键代码解释

### 4.1 UploadCVServlet：上传入口和预填控制

文件：
[UploadCVServlet.java](/D:/workspace/TAs_system/TA_Recruitment_System/src/com/group19/servlet/UploadCVServlet.java)

关键位置：
- `41-56`：接收上传请求，获取 `studentId` 和 `cvFile`
- `56`：调用 `cvService.uploadCv(...)`
- `58-70`：上传和解析成功后，将结果放入 request 并转发到 `profile.jsp`
- `89-103`：将提取出来的 education / skills / experience 回填到 `TA` 对象

可以这样解释：

这部分是 US03 的入口。Servlet 本身不负责解析简历，而是负责接收请求、调用业务层，并把解析结果送回页面展示。

这里我没有在上传后直接重定向保存提取结果，而是先把结果预填到表单，再让用户确认和修改。这样做的原因是，验收标准要求“助教可以在保存前查看并修改提取的值”。

### 4.2 CVService：业务逻辑层

文件：
[CVService.java](/D:/workspace/TAs_system/TA_Recruitment_System/src/com/group19/service/CVService.java)

关键位置：
- `21-34`：校验 studentId、上传文件、目录是否合法
- `36-45`：检查 TA 档案是否存在
- `48-55`：保存上传文件到 `uploads`
- `57-62`：保存 CV 路径，并调用解析工具提取内容

可以这样解释：

这一层负责真正的业务逻辑，而不是把逻辑写死在 Servlet 里。  
它先做输入校验，再保存文件，然后调用 `CVParserUtil.extract(...)` 提取简历内容，最后把“更新后的 profile + 提取结果”封装后返回。

这样做的好处是分层更清晰，后续如果要替换解析方式，只需要改 Service 或解析工具，不需要改 JSP。

### 4.3 CVParserUtil：简历解析逻辑

文件：
[CVParserUtil.java](/D:/workspace/TAs_system/TA_Recruitment_System/src/com/group19/util/CVParserUtil.java)

关键位置：
- `51-64`：`extract()` 是总入口
- `57-60`：根据文件类型决定如何读取内容
- `67-96`：`parseFromText()` 提取 education / skills / experience
- `99-125`：按 section 标题提取
- `190-213`：skills 提取失败时的关键词兜底
- `242-258`：读取 `docx` 中的 `word/document.xml`

可以这样解释：

这里我没有引入复杂 AI 模型，而是实现了一个轻量的规则解析器。  
它优先根据简历中的常见标题，例如 `Education`、`Skills`、`Experience` 来做分段提取；如果标题不标准，就用关键词做兜底。

这样做的原因是：
- 课程项目更重视流程完整、稳定可运行
- 规则解析更容易解释和维护
- 即使提取不完全，用户仍然可以手动修改

### 4.4 profile.jsp：预填和可编辑展示

文件：
[profile.jsp](/D:/workspace/TAs_system/TA_Recruitment_System/web/WEB-INF/jsp/profile.jsp)

最重要的是，用户看到的不是一个只读结果，而是一个可以直接编辑的表单，这正是 US03 的核心要求之一。

## 5. 为什么增加 CVUploadResult

文件：
[CVUploadResult.java](/D:/workspace/TAs_system/TA_Recruitment_System/src/com/group19/dto/CVUploadResult.java)

解释：

上传成功之后，系统需要同时返回两类信息：

1. 更新后的 `TA profile`
2. 从简历中提取出的 `CVExtractedInfo`

如果直接返回一个对象会导致职责混乱，所以我新增了一个 DTO 来封装结果。这样返回结构更清晰，也更容易在 Servlet 中使用。

## 6. 为什么这样设计

这部分是答辩时一定要强调的设计理由：

1. **符合 MVC 分层**
   - Servlet 负责请求控制
   - Service 负责业务逻辑
   - JSP 负责展示
   - Model 负责承载数据

2. **符合验收标准**
   验收标准要求“提取后预填，并且保存前可以修改”，所以不能上传后直接写死到数据库，必须先回显给用户确认。

3. **保持流程可控**
   规则解析不一定百分之百准确，所以保留人工修改步骤，保证系统即使提取不完整也依然可用。

4. **便于后续扩展**
   如果以后要接更复杂的简历解析方式，可以只替换解析工具或 Service，不需要推翻整体页面和控制流程。



### 问题 1：为什么上传成功后不用 redirect，而是 forward 到 profile 页面？

回答：

因为这一步的目标不是立即持久化提取结果，而是先把结果预填给用户看。  
使用 forward 可以把提取结果直接放在 request 中渲染出来，用户确认后再保存，这样更符合 US03 的交互要求。

### 问题 2：为什么不直接把提取结果写进数据文件？

回答：

因为验收标准要求用户可以在保存前查看和修改。  
如果上传后直接写入，就可能覆盖原有档案信息，也不利于用户确认提取是否正确。

### 问题 3：你的解析是不是 AI？

回答：

当前不是复杂 AI 模型，而是轻量规则解析。  
课程项目阶段更重要的是把业务流程完整打通，并保证实现简单、稳定、可解释。

### 问题 4：如果简历格式不标准怎么办？

回答：

当前方案优先按 section 标题提取，失败时再走关键词兜底。  
即使提取不完整，用户依然可以手动修改后保存，所以不会阻断整个流程。

### 问题 5：你这部分体现了什么工程设计思想？

回答：

主要体现了分层设计和可维护性。  
我把上传处理、解析逻辑、数据保存和页面展示拆开，实现上遵循 MVC，这样代码更清晰，也更容易扩展和测试。
