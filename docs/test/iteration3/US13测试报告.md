# US13 测试报告

## 1. 基本信息

- Story ID: US13
- Story 名称: 检测时间冲突或过载
- 测试方式: 手工功能测试
- 测试日期: 2026-05-19
- 测试人员: GuoYixuan

## 2. 测试目标

验证系统是否满足 US13 的验收标准：

1. 系统能够标记时间冲突或超过自定义阈值的小时数。
2. 管理员工作量视图中出现警告信息。
3. 每条警告包含简短原因，例如 `Time conflict` 或 `Hours limit exceeded`。

## 3. 测试环境

- OS: Windows
- JDK: 21
- Tomcat: 10.1.49
- Browser: Chrome / Edge
- 应用地址: `http://localhost:8080/TA_Recruitment/login`
- 相关页面: `/TA_Recruitment/mo/applications?jobId=job-001`

- Role: `MO`

### TA Account

- Username: `ta001`

## 5. 测试数据

本次测试使用同一个 TA 的多条 active application 记录，使其满足以下条件：

- 同一个 TA 存在多条 active application。
- 总工作小时数超过系统阈值。
- 至少两条岗位 schedule 存在时间重叠。

系统配置的小时阈值：

```xml
<context-param>
    <param-name>maxWeeklyWorkloadHours</param-name>
    <param-value>20</param-value>
</context-param>
```

实际页面中显示的测试结果：

- Current workload: `7 active applications, 43 assigned hours`
- Workload warnings: `1`
- Warning reasons:
  - `Time conflict`
  - `Hours limit exceeded`

## 6. 测试步骤

1. 启动 Tomcat。
2. 打开 `http://localhost:8080/TA_Recruitment/login`。
3. 使用 MO 账号 `mo001 / mo123456` 登录。
4. 进入 MO Job List。
5. 点击 `Introduction to Java Teaching Assistant` 的 `View Applicants`。
6. 查看 Applicant Review 页面中的 summary 区域和 applicant table。
7. 打开对应 applicant 的 profile，检查详情页是否显示同样的 workload warning。

## 9. 缺陷与修复记录

| 缺陷 ID | 现象 | 原因 | 修复方式 | 回归结果 |
| --- | --- | --- | --- | --- |
| BUG-US13-01 | 初始 applicant review 页面只有 active application 数量，没有显示时间冲突或小时超限原因 | 原有 workload 逻辑只统计申请数量，没有解析 job hours 和 schedule | 在 `ApplicantReviewService` 中新增 workload 汇总、hours 解析、schedule conflict 检测，并在表格中展示 warning reasons | Pass |

## 10. 测试结论

US13 已通过本次手工测试。

系统现在能够在 MO 的 applicant review 工作量视图中检测并显示 TA 的时间冲突和小时数超限问题。警告信息能够明确给出原因，符合 US13 的验收标准。
