# US13 测试报告

## 1. 基本信息

- Story ID: US13
- Story 名称: 检测时间冲突或过载
- 测试方式: 手工功能测试
- 测试日期: 2026-05-19
- 测试人员: Group 19

## 2. 测试目标

验证系统是否满足 US13 的验收标准：

1. 系统能够标记时间冲突或超过自定义阈值的小时数。
2. 管理员工作量视图中出现警告信息。
3. 每条警告包含简短原因，例如 `Time conflict` 或 `Hours limit exceeded`。

## 3. 测试环境

- OS: Windows
- JDK: 21
- Tomcat: 10.1.49
- Browser: Chrome / Edge
- 应用地址: `http://localhost:8080/TA_Recruitment/login`
- 相关页面: `/TA_Recruitment/admin/workload`

## 4. 测试账号

### Admin Account

- Username: `admin001`
- Password: `admin123456`
- Role: `ADMIN`

### 对照账号

- TA: `ta001 / ta123456`
- MO: `mo001 / mo123456`

## 5. 测试数据

本次测试使用管理员工作量视图中的 accepted applications 作为工作量来源。

测试数据应满足以下条件：

- 同一个 TA 存在多条 `ACCEPTED` application。
- 对应 job 的 `hours` 总和超过系统阈值。
- 至少两条 accepted assignment 的 `schedule` 存在时间重叠。

系统配置的小时阈值：

```xml
<context-param>
    <param-name>maxWeeklyWorkloadHours</param-name>
    <param-value>20</param-value>
</context-param>
```

## 6. 测试步骤

1. 启动 Tomcat。
2. 打开 `http://localhost:8080/TA_Recruitment/login`。
3. 使用 Admin 账号 `admin001 / admin123456` 登录。
4. 进入 `/admin/workload`。
5. 查看 TA Workload Dashboard 的 summary 区域。
6. 查看 workload table 中每个 TA 的 `Warnings` 列。
7. 检查存在时间重叠的 assigned position 是否显示 conflict 标记。
8. 使用 TA 或 MO 账号尝试访问 `/admin/workload`，验证权限控制。

## 7. 测试用例与结果

| 用例 ID | 测试场景 | 操作步骤 | 预期结果 | 结论 |
| --- | --- | --- | --- | --- |
| US13-TC01 | Admin 访问工作量视图 | Admin 登录后进入 `/admin/workload` | 页面正常打开，显示 TA workload dashboard | Pass |
| US13-TC02 | 非 Admin 访问工作量视图 | 使用 TA 或 MO 访问 `/admin/workload` | 系统拒绝访问，返回 403 或重定向到正确页面 | Pass |
| US13-TC03 | 显示总工作量 | 查看 `Total assigned hours` | 系统按 accepted assignments 汇总小时数 | Pass |
| US13-TC04 | 检测超过小时阈值 | 使用总小时数超过 20 的 accepted assignments | `Warnings` 列显示 `Hours limit exceeded` | Pass |
| US13-TC05 | 检测时间冲突 | 使用 schedule 重叠的 accepted assignments | `Warnings` 列显示 `Time conflict`，冲突岗位显示 `conflict` 标记 | Pass |
| US13-TC06 | Summary 显示 warning 数量 | 查看 summary 中的 `Workload warnings` | 系统统计包含 warning 的 TA 数量 | Pass |

## 8. 实际页面表现

TA Workload Dashboard 页面应显示：

- `Workload warnings` summary card。
- 含 warning 的 TA 行使用浅黄色背景突出显示。
- `Warnings` 列显示 `Time conflict` 或 `Hours limit exceeded`。
- 发生 schedule 重叠的 assigned position 显示 `conflict` 标签。

## 9. 缺陷与修复记录

| 缺陷 ID | 现象 | 原因 | 修复方式 | 回归结果 |
| --- | --- | --- | --- | --- |
| BUG-US13-01 | US13 警告错误地显示在 MO applicant review 页面中 | 将“管理员”误解为 MO，而不是第三角色 ADMIN | 将 US13 逻辑迁移到 `/admin/workload`，由 `WorkloadService` 基于 accepted assignments 计算警告 | Pass |

## 10. 测试结论

US13 已迁移到 Admin 工作量视图。

系统现在由 `ADMIN` 角色在 `/admin/workload` 页面查看 TA 的工作量警告，MO 仍负责岗位和申请管理，不再承担 US13 管理员工作量警告功能。
