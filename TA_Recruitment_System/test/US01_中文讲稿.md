# US01 中文讲稿

我这次主要负责的是 `US01`，也就是助教申请人个人资料的创建和编辑功能。这个功能对应的目标是让 TA 可以录入自己的基本信息，后续模块负责人可以查看这些资料用于招聘筛选。

在数据结构上，我先定义了 TA 的实体类，比如 `TA.java`。这个类里包含了 `name`、`studentId`、`email`、`programme`、`skills`、`availability` 这些字段，还有对应的 getter 和 setter。这样前端表单提交上来的数据，后端就可以统一封装成一个 TA 对象。

在数据存储方面，我没有使用数据库，而是按照课程要求把数据保存到 JSON 文件。这个部分主要由 `TADao.java` 和 `JsonFileUtil.java` 完成。`JsonFileUtil` 负责通用的 JSON 读写，比如读取 `tas.json` 里的列表，或者把更新后的列表重新写回文件。`TADao` 则在这个基础上实现了两个核心功能，一个是根据 `studentId` 查找已有资料，另一个是 `saveOrUpdate`，也就是如果学号已经存在就更新，不存在就新增。

在业务逻辑上，我把校验和保存流程放在了 `ProfileService.java`。这里最重要的方法是 `saveProfile`，它会先检查姓名、学号、邮箱、专业、技能和可用时间这些字段是不是为空。如果邮箱格式不正确，也会直接返回错误。比如代码里用了正则去验证邮箱格式，然后把错误信息拼接后返回给前端。校验通过之后，才会创建 TA 对象并调用 DAO 把数据写入 JSON 文件。这里我还加了一个 `updatedAt` 字段，方便记录最近一次修改时间。

在控制器层，我实现了 `ProfileServlet.java`。这个 Servlet 主要处理两类请求。第一类是 `doGet`，也就是用户通过学号重新打开资料的时候，Servlet 会读取 `studentId` 参数，然后调用 `profileService.getProfileByStudentId` 去查找已有数据，如果查到了，就把这个 TA 对象放到 request 里，再转发到 JSP 页面显示。第二类是 `doPost`，也就是用户点击保存的时候，Servlet 会从表单中获取 `name`、`studentId`、`email`、`programme`、`skills`、`availability` 这些参数，然后调用 `saveProfile`。如果保存成功，就重定向回当前页面并显示成功提示；如果失败，就把用户刚才输入的数据重新回填到页面上，同时显示错误信息。

在页面层，我实现了 `profile.jsp`。这个页面有两个部分。上面一部分是“通过学号打开已有资料”，用户输入学号后可以重新加载之前保存的数据。下面一部分是资料表单，里面有姓名、学号、邮箱、专业、技能和可用时间这些输入框。页面里通过 `${profile.name}`、`${profile.studentId}` 这种方式，把后端传过来的数据回填到表单中，所以用户重新打开资料时可以直接看到之前保存的内容。页面里也会显示 `${error}` 和 `${success}`，用来提示保存失败或者保存成功。

配置方面，我还在 `web.xml` 里注册了 `ProfileServlet`，把它映射到 `/profile` 路径。这样访问这个路径时，Tomcat 就会自动把请求交给这个 Servlet 处理。

我负责的是 US01 的完整实现。具体包括 TA 实体类设计、基于 JSON 的数据存储、资料保存和查询的 DAO、表单校验和业务逻辑的 Service、处理请求的 Servlet，以及前端的 JSP 页面回填和提示信息显示。这样就把创建资料、保存资料、重新打开资料和编辑资料这一整条流程打通了。

## 老师如果追问“你最核心的代码是哪几段”

1. `ProfileService.saveProfile()`
这是保存逻辑的核心，负责校验输入并调用 DAO 持久化。

2. `TADao.saveOrUpdate()`
这是数据更新的核心，通过学号判断是新增还是更新。

3. `ProfileServlet.doGet()` 和 `doPost()`
这两个方法分别负责重新打开资料和提交保存资料，是前后端交互的入口。
